# pplx-export

`pplx-export` هو واجهة سطر الأوامر للأرشفة: فهو يسحب فهارس المحادثات من Perplexity، ويصدر سلاسل المحادثات إلى الأرشيف المحلي، ويحافظ على المشاهدات المشتقة (فهرس المساحة، مقتطف cron). تغطي هذه الصفحة الأوامر الفرعية لجانب الالتقاط — `index`، `space-index`، `export`، `batch`، `spaces`، `sync-space`، `schedule` — بالإضافة إلى أمر الإعداد لمرة واحدة `init`. توجد الأوامر الفرعية للردم/الإصلاح في [maintenance-commands.md](maintenance-commands.md)؛ ويتم تغطية واجهة سطر الأوامر للاستعلام في [pplx-ask.md](pplx-ask.md).

<a id="common-options" data-pplx-source-anchor="true"></a>
## الخيارات المشتركة

يقبل كل أمر فرعي هذه العلامات (المعرفة مرة واحدة في `pplx_export/commands/common.py`):

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| `--account NAME` | الحساب المستهدف. عندما لا يتطابق البريد الإلكتروني لملف تعريف الارتباط مع البريد الإلكتروني المسجل، يتم تعداد رموز جلسة المتصفح لكل حساب للتبديل تلقائيًا | `default_account` من تكوين المستخدم |
| `--config PATH` | ملف تكوين المستخدم (سجل الحسابات). الأولوية: `--config` > env `PPLX_EXPORT_CONFIG` > `~/.config/pplx-export/config.toml` | سلسلة البحث الافتراضية |
| `--site NAME` | محول الموقع | `perplexity` |
| `--out DIR` | جذر إخراج الأرشيف | `./web_archive` |
| `--cookies-from BROWSER` | استيراد ملفات تعريف الارتباط من متصفح (`edge`/`chrome`/`firefox`/`safari`/`brave`…) | — |
| `--cookies FILE` | ملف تعريف ارتباط Netscape أو ملف تعريف ارتباط JSON | — |
| `--transport MODE` | `cookie` = طلبات مباشرة عبر ملفات تعريف الارتباط؛ `webbridge` = جلب داخل سياق صفحة المتصفح | `cookie` |
| `-v`, `--verbose` | إخراج DEBUG (تتبعات الطلب، القرارات الداخلية)؛ قابل للتكرار | off |
| `--log-file [PATH]` | كتابة السجل الكامل على القرص؛ بدون قيمة، المسار التلقائي `<out>/index/logs/<cmd>-<timestamp>.log` | off |

- `--cookies-from` / `--cookies` متنافيان مع `--transport webbridge` — يعمل الجسر في سياق الصفحة ويحمل بالفعل ملفات تعريف ارتباط المتصفح.
- `pplx-export --version` يطبع إصدار الحزمة ويخرج (على المستوى الأعلى فقط، وليس علامة أمر فرعي).
- تسجيل الحساب، مصادر ملفات تعريف الارتباط والتبديل بين حسابات متعددة: [configuration.md](configuration.md). أين يقع كل شيء على القرص: [archive-layout.md](archive-layout.md).

## init

اكتشاف الحسابات من ملفات تعريف ارتباط المتصفح وكتابة تكوين المستخدم — البديل التلقائي لنسخ `config.example.toml` يدويًا (انظر [configuration.md](configuration.md)).

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| `--force` | الكتابة فوق ملف تكوين موجود | off (يرفض الكتابة فوق) |
| `--create-bot-space [TITLE]` | إنشاء مساحة BOT عبر API عندما لا يتطابق عنوان مساحة (عملية كتابة على الحساب)؛ عنوان TITLE صريح يوجه كلاً من المطابقة والإنشاء، وإلا يأتي العنوان من `--bot-title`؛ بدون هذه العلامة `[bot_space]` يُكتب فارغًا | off |
| `--bot-title TITLE` | عنوان المساحة المستخدم لمطابقة مساحة موجودة وتسمية مساحة منشأة | `BOT` |
| *(تنطبق الخيارات المشتركة)* | علامات مصدر ملفات تعريف الارتباط تختار مكان اكتشاف الحسابات؛ لـ `init` فقط، `--config` هو مسار **الكتابة** (يتم تخطي تحميل التكوين الصارم) | |

السلوكيات الرئيسية:

- تعداد الرموز: يتم جمع ملفات تعريف ارتباط الجلسة لكل حساب (`__Secure-pplx.session.<uid>`) من مخازن المتصفح — أو، مع `--cookies FILE`، مسحها ضوئيًا من ملف تعريف الارتباط (قد يحمل التصدير الكامل عدة حسابات). بدون رموز قابلة للتعداد، يتم اختبار الجلسة النشطة الحالية فقط.
- اختبار الجلسة: يتم تجربة كل رمز ضد `GET /api/auth/session` لمعرفة البريد الإلكتروني / اسم العرض للحساب؛ يتم تخطي الرموز التي تفشل أو لا ترجع بريدًا إلكترونيًا مع تحذير.
- تجميع السجل: يتم اشتقاق مفتاح كل حساب من الجزء المحلي للبريد الإلكتروني (التصادمات تحصل على لاحقات `-2`/`-3`…)؛ يتم تعيين `default_account` على الحساب النشط حاليًا، وإلا الأول المكتشف.
- مساحة BOT: تتم مطابقة مساحة بالعنوان الدقيق (غير حساس لحالة الأحرف) عبر `list_user_collections`؛ عندما لا يتطابق شيء، `--create-bot-space [TITLE]` ينشئها فورًا (TITLE صريح يتجاوز `--bot-title` لكل من المطابقة والإنشاء)، وإلا يُترك `[bot_space]` فارغًا.
- يُكتب TOML بشكل ذري (ملف مؤقت + إعادة تسمية) بأذونات 0600، ولا يتم أبدًا الكتابة فوق ملف موجود بدون `--force`. ينتهي الأمر بسطر ملخص JSON: مسار التكوين، مفاتيح الحساب، الحساب الافتراضي، uuid/slug مساحة BOT.
- `--transport webbridge` مرفوض — لا يمكن لقناة سياق الصفحة تعداد الرموز لكل حساب.

```bash
pplx-export init                          # write the default ~/.config/pplx-export/config.toml
pplx-export init --create-bot-space [TITLE]  # create the BOT space when no title matches (custom title optional)
pplx-export init --config /path/to/config.toml --force   # custom path, overwrite allowed
```

## index

جلب قائمة المحادثات الكاملة للحساب (GraphQL) وكتابة الفهرس الرئيسي `index/library_<account>.json` — خط الأساس الذي تتفاضل ضده كل الأوامر الأخرى.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| *(الخيارات المشتركة فقط)* | | |

السلوكيات الرئيسية:

- يحافظ على إثراء `search_mode` الذي كتبه `search-mode-backfill`: صفوف الفهرس لا تحمله أصلاً، لذلك عند التحديث يتم دمجه مرة أخرى من الفهرس القديم بواسطة `entryUUID`.
- قم بتشغيله قبل `batch`، `sync-space` و `sync-deleted` — فروقاتها تكون حديثة بقدر هذا الفهرس فقط.

```bash
pplx-export index --account alice
```

## space-index

استخراج قائمة محادثات "الكل" لمساحة واحدة — بما في ذلك السلاسل المشتركة من قبل أعضاء آخرين — إلى `index/space_<slug>.json`.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| `SPACE_URL` (موضعي) | عنوان URL لصفحة المساحة | مطلوب |
| `--transport webbridge` | استخدام مسار عرض المتصفح القديم بدلاً من REST | `cookie` (REST مباشر) |

السلوكيات الرئيسية:

- المسار الافتراضي هو REST مباشر: `list_collection_threads` عبر نقل ملفات تعريف الارتباط مع ترقيم الصفحات بالإزاحة؛ تتضمن الصفوف `context_uuid` و `answer_preview`.
- مع `--transport webbridge` يتراجع إلى تمرير صفحة المساحة المقدمة وكشط خصائص الصف — نسخة احتياطية في حال تغير هيكل REST.
- تُكتب الصفوف من الأحدث إلى الأقدم بواسطة `lastUpdated`.

```bash
pplx-export space-index "https://www.perplexity.ai/spaces/<space-slug>" --account alice
```

## export

تصدير سلسلة محادثات واحدة (URL أو UUID مجرد) إلى دليل الأرشيف الخاص بها `<out>/<account-folder>/<mode>/<thread-dir>/`.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| `THREAD` (موضعي) | عنوان URL للسلسلة أو UUID | مطلوب |
| `--force` | إعادة التصدير حتى عندما يكون `lastUpdated` دون تغيير | off |

السلوكيات الرئيسية:

- إذا كانت النسخة المؤرشفة محدثة بالفعل، يتم تخطي التصدير بدون كتابات؛ `--force` يتجاوز الفحص.
- يتم أخذ `lastUpdated` من فهرس المكتبة المحلية عندما تكون السلسلة مدرجة هناك (نفس الدلالات والتنسيق مثل `batch`)، مع الرجوع إلى قيمة المنصة بخلاف ذلك.
- يتم تسجيل الحالات النهائية بأدب، بدون تتبع: `ENTRY_DELETED` يضع علامة `deleted` في `batch_state.json`، `ENTRY_EXPIRED` يضع علامة `expired` — يتم الاحتفاظ بالأرشيف المحلي الموجود دون تغيير في كلتا الحالتين.
- التصدير الناجح يكتب `ok` إلى `index/batch_state.json`، بحيث تحسب الخطة المتزايدة السلسلة على أنها "مصدرة ودون تغيير".
- ما يقع في دليل السلسلة: [archive-layout.md](archive-layout.md)؛ خط أنابيب التصدير نفسه: [../architecture/export-pipeline.md](../architecture/export-pipeline.md).

```bash
pplx-export export "https://www.perplexity.ai/search/<thread-uuid>" --account alice
```

## batch

تصدير شامل لسلاسل المحادثات لحساب — المحرك اليومي، مع توقف مبكر تزايدي ونقاط تفتيش قابلة للاستئناف.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| `--force` | إعادة تصدير جميع السلاسل (باستثناء الحالات النهائية) | off |
| `--full` | فحص كامل: السلاسل دون تغيير لا تزال تُتخطى، ولكن لا توقف مبكر | off |
| `--limit N` | معالجة أول N صف فقط من القائمة (الأحدث أولاً) | الكل |
| `--mode MODE` | تصدير سلاسل `search` / `deep-research` / `computer` / `council` / `study` فقط | جميع الأوضاع |
| `--delay-min SEC` | الحد الأدنى للفاصل العشوائي بين السلاسل | `10` |
| `--delay-max SEC` | الحد الأعلى للفاصل العشوائي بين السلاسل | `20` |

السلوكيات الرئيسية:

- يتطلب `index/library_<account>.json` — قم بتشغيل `index` أولاً.
- **التوقف المبكر التزايدي** الافتراضي: يتم فرز القائمة من الأحدث إلى الأقدم ويتم اقتطاع التشغيل الخلفي لسلاسل "مصدرة ودون تغيير" بالكامل؛ الفجوات التي تتركها التشغيلات المتقطعة (خطأ/لم يتم تصديرها) تقع فوق تلك اللاحقة ولا تزال تُصلح. `--full` يعطل التوقف المبكر (حاجز دوري، أو عند الاشتباه بفجوات في الأرشيف)؛ `--force` يعيد تصدير كل شيء باستثناء الحالات النهائية، التي لا يعاد محاولتها أبدًا. الدلالات الكاملة: [incremental-sync.md](incremental-sync.md).
- تصفية `--mode`: الصفوف التي تحمل `search_mode` (الحقل الموثوق من المنصة المثرى بواسطة `search-mode-backfill`) تطابق تمامًا عبر `SEARCH_MODE_MAP` — على هذا المسار `--mode search` لم يعد يسحب سلاسل deep-research/council/study. الصفوف بدون `search_mode` ترجع إلى استدلالات الفهرس: `computer` = الوضع `COMPUTER`؛ `deep-research` = displayModel `pplx_alpha`؛ `council` = `pplx_agentic_research`؛ `study` = `pplx_study`؛ `search` = الصفوف المتبقية من الوضع `SEARCH` (بما في تلك الأنواع الثلاثة — قم بتصفيتها بدقة عن طريق تصدير الأوضاع المحددة بشكل منفصل).
- يتم حفظ الحالة إلى `index/batch_state.json` بعد كل سلسلة — قاطع وأعد التشغيل بحرية.
- فشل سريع للمصادقة: 3 استجابات 401/403 متتالية تلغي التشغيل (ملف تعريف ارتباط منتهي الصلاحية لا يمكنه الشفاء الذاتي، والاستمرار سيفشل مئات السلاسل واحدة تلو الأخرى).
- الإيقاع: توقف عشوائي `--delay-min`–`--delay-max` بين السلاسل؛ يتم تأجيل 429/5xx بواسطة طبقة النقل. التفاصيل: [rate-limiting.md](rate-limiting.md).
- يتم تسجيل السلاسل التي تصل إلى متغيرات إجابة معاد كتابتها في `index/answer_variants_log.jsonl` مع تحذير للتعامل معها يدويًا في أقرب وقت ممكن (انظر [../reference/api/api-responses-errors.md](../reference/api/api-responses-errors.md)).

```bash
pplx-export batch --account bob --mode deep-research --limit 50
```

## spaces

إعادة بناء فهرس عرض المساحة — صفحة Markdown واحدة لكل مساحة بالإضافة إلى سجل `spaces.json` — من فهارس المكتبة المحلية.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| `--fetch-meta` | تحديث بيانات المالك/العضو قبل إعادة البناء | off |

السلوكيات الرئيسية:

- بدون `--fetch-meta` يكون الأمر محليًا بحتًا (صفر شبكة): يجمع السلاسل لكل مساحة عبر جميع ملفات `library_*.json`، مع إحصائيات الحساب المشارك وروابط خلفية لأدلة السلاسل المصدرة.
- يذهب الإخراج إلى `./spaces/` نسبة إلى دليل العمل الحالي — قم بتشغيله من الدليل الذي يحتوي على `web_archive/` حتى يتم حل الروابط الخلفية في صفحات المساحة.
- `--fetch-meta` أولاً يحدث ذاكرة التخزين المؤقت للمالك/العضو لكل مساحة عبر `get_collection` (طلب واحد لكل مساحة، فاصل 3 ثوانٍ) إلى `index/space_meta.json`؛ عندما لا يتمكن الحساب الحالي من رؤية مساحة، يتم إعادة محاولة حساب يمكنه تلقائيًا (تتبدل ملفات تعريف الارتباط من تلقاء نفسها).

```bash
pplx-export spaces --fetch-meta --account alice
```

## sync-space

مزامنة حقل `space` لملفات `thread.json` المؤرشفة بالفعل مع الفهرس الحالي — محلي بحت، صفر شبكة.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| *(الخيارات المشتركة فقط؛ فقط `--out` مهم)* | | |

السلوكيات الرئيسية:

- المتطلب الأساسي: قم بتشغيل `index` أولاً — `library_*.json` المحدث هو مصدر الحقيقة لملكية المساحة الحالية.
- يقارن مسارات المساحة لكل سلسلة ويصحح `thread.json` في مكانه عند الاختلاف؛ يتم تسجيل أول 30 تغييرًا.
- بعد أي تغيير، يتم إعادة بناء فهرس `spaces/` تلقائيًا بالتوازي.

```bash
pplx-export index --account alice && pplx-export sync-space
```

## schedule

حساب خطة التصدير التزايدية لهذه الجولة وكتابة مقتطف cron يمكن لـ cron النظام استدعاؤه مباشرة.

| العلامة | المعنى | القيمة الافتراضية |
|---|---|---|
| *(الخيارات المشتركة فقط)* | | |

السلوكيات الرئيسية:

- يجلب فهرسًا حيًا ويبلغ عن الخطة كأعداد إجمالي/جديد/محدث، باستخدام نفس دالة التوقف المبكر البحتة (`plan_incremental`) مثل `batch` — انظر [incremental-sync.md](incremental-sync.md).
- يكتب `<out>/index/cron_snippet.txt` يحتوي على سطر `17 3 * * *` واحد من النموذج `cd '<archive-parent>' && '<abs-path-to-pplx-export>' batch --account '<account>' --out '<abs-archive-root>'` — المسارات مطلقة ومقتبسة لأن cwd و PATH لـ cron غير متوقعين. يتم حل مسار الملف التنفيذي عبر `shutil.which`؛ عندما يفشل ذلك، يتراجع المقتطف إلى اسم `pplx-export` المجرد.
- التشغيلات المجدولة هي تزايدية فقط حسب التصميم؛ قم بتشغيل `batch --full` يدويًا كحاجز دوري.

```bash
pplx-export schedule --account alice
```
