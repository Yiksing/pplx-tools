# pplx-export

`pplx-export` — это CLI-архиватор: он извлекает индексы бесед из Perplexity, экспортирует треды в локальный архив и поддерживает производные представления (индекс пространств, фрагмент cron). Эта страница охватывает подкоманды захвата — `index`, `space-index`, `export`, `batch`, `spaces`, `sync-space`, `schedule` — а также команду однократной настройки `init`. Подкоманды обратного заполнения/восстановления находятся в [maintenance-commands.md](maintenance-commands.md); CLI запросов описан в [pplx-ask.md](pplx-ask.md).

<a id="common-options" data-pplx-source-anchor="true"></a>
## Общие параметры

Каждая подкоманда принимает эти флаги (определены один раз в `pplx_export/commands/common.py`):

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--account NAME` | Целевая учётная запись. Если email из cookie не совпадает с зарегистрированным email, перечисляются токены сеанса браузера для каждой учётной записи для автоматического переключения | `default_account` из конфигурации пользователя |
| `--config PATH` | Файл конфигурации пользователя (реестр учётных записей). Приоритет: `--config` > env `PPLX_EXPORT_CONFIG` > `~/.config/pplx-export/config.toml` | цепочка поиска по умолчанию |
| `--skip-auth-check` | Пропустить начальный зонд сеанса атрибуции учётной записи и доверять текущему входу, избегая долгого ожидания запуска при плохом сетевом соединении; `batch` выполняет отложенную проверку учётной записи, если накапливаются ошибки — см. [Configuration](configuration.md) | выкл |
| `--site NAME` | Адаптер сайта | `perplexity` |
| `--out DIR` | Корневой каталог вывода архива | `--out` > config `archive_root` > `./web_archive` |
| `--cookies-from BROWSER` | Импортировать cookies из браузера (`edge`/`chrome`/`firefox`/`safari`/`brave`…) | — |
| `--cookies FILE` | Файл cookie в формате Netscape или JSON | — |
| `--transport MODE` | `cookie` = запросы напрямую через cookie; `webbridge` = выборка в контексте страницы браузера | `cookie` |
| `-v`, `--verbose` | Вывод DEBUG (трассировка запросов, внутренние решения); повторяемый | выкл |
| `--log-file [PATH]` | Записать полный журнал на диск; без значения — автоматический путь `<out>/index/logs/<cmd>-<timestamp>.log` | выкл |

- `--cookies-from` / `--cookies` взаимно исключают `--transport webbridge` — мост работает в контексте страницы и уже несёт cookies браузера.
- `pplx-export --version` выводит версию пакета и завершает работу (только верхний уровень, не флаг подкоманды).
- Регистрация учётной записи, источники cookie и переключение между несколькими учётными записями: [configuration.md](configuration.md). Где всё сохраняется на диске: [archive-layout.md](archive-layout.md).

## init

Обнаружить учётные записи из cookies браузера и записать конфигурацию пользователя — автоматическая альтернатива ручному копированию `config.example.toml` (см. [configuration.md](configuration.md)).

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--force` | Перезаписать существующий файл конфигурации | выкл (отказывается перезаписывать) |
| `--create-bot-space [TITLE]` | Создать пространство BOT через API, когда ни одно название пространства не совпадает (операция записи в учётной записи); явный TITLE управляет как сопоставлением, так и созданием, иначе название берётся из `--bot-title`; без этого флага `[bot_space]` записывается пустым | выкл |
| `--bot-title TITLE` | Название пространства, используемое как для сопоставления существующего пространства, так и для именования созданного | `BOT` |
| *(применяются общие параметры)* | Флаги источника cookie определяют, где обнаруживаются учётные записи; только для `init` `--config` — это путь **записи** (строгая загрузка конфигурации пропускается) | |

Ключевое поведение:

- Перечисление токенов: токены сеанса для каждой учётной записи (`__Secure-pplx.session.<uid>`) собираются из хранилищ браузера — или, с `--cookies FILE`, сканируются из файла cookie (полный экспорт может содержать несколько учётных записей). Если перечисляемых токенов нет, проверяется только текущий активный сеанс.
- Зонд сеанса: каждый токен проверяется на `GET /api/auth/session`, чтобы узнать email/отображаемое имя учётной записи; токены, которые не проходят проверку или не возвращают email, пропускаются с предупреждением.
- Сборка реестра: ключ каждой учётной записи формируется из локальной части email (коллизии получают суффиксы `-2`/`-3`…); `default_account` устанавливается на текущую активную учётную запись, иначе на первую обнаруженную.
- Пространство BOT: пространство сопоставляется по точному названию (без учёта регистра) через `list_user_collections`; если ничего не совпадает, `--create-bot-space [TITLE]` создаёт его на месте (явный TITLE переопределяет `--bot-title` как для сопоставления, так и для создания), иначе `[bot_space]` остаётся пустым.
- TOML записывается атомарно (временный файл + переименование) с правами 0600, и существующий файл никогда не перезаписывается без `--force`. Команда завершается строкой JSON с итогом: путь конфигурации, ключи учётных записей, учётная запись по умолчанию, uuid/слаг пространства BOT.
- `--transport webbridge` отклоняется — канал контекста страницы не может перечислять токены для каждой учётной записи.

```bash
pplx-export init                          # write the default ~/.config/pplx-export/config.toml
pplx-export init --create-bot-space [TITLE]  # create the BOT space when no title matches (custom title optional)
pplx-export init --config /path/to/config.toml --force   # custom path, overwrite allowed
```

## index

Обновить индекс списка бесед учётной записи `index/library_<account>.json` — базовый уровень, с которым сравниваются все остальные команды.

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--full` | Пролистать всю библиотеку и перезаписать индекс; сбрасывает инкрементальный счётчик | инкрементально |

Ключевое поведение:

- **Инкрементально по умолчанию.** Пролистывает сначала новые и останавливается, когда полная страница (`_STOP_RUN`) последовательных строк уже известна и не изменилась, затем объединяет полученную голову с существующим индексом — старые строки переносятся дословно (без потерь). Первый запуск или любой запуск без существующего индекса — полный обход.
- **`--full`** пролистывает всё и перезаписывает индекс; используйте его как периодический интерфейс сверки.
- **Слепое пятно инкрементального пути:** удалённые *удаления* и *изменения пространств* старых тредов никогда не появляются в полученной голове, поэтому не наблюдаются. Полномочия на удаление остаются за `sync-deleted --online`. Документ индекса отслеживает `incremental_runs_since_full`; после достаточного количества инкрементальных запусков он предупреждает вас о необходимости запустить `--full` (и `sync-deleted --online`).
- Сохраняет обогащение `search_mode`, записанное `search-mode-backfill`, объединённое обратно `entryUUID`.
- Запускайте его перед `batch`, `sync-space` и `sync-deleted` — их различия актуальны настолько, насколько свеж этот индекс.

```bash
pplx-export index --account alice          # incremental refresh
pplx-export index --account alice --full   # full sweep + reconciliation front-end
```

## sync

Высокочастотная удобная точка входа: **инкрементальный `index` + инкрементальный `batch`**, ориентированный только на беседы.

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--full` | Полная сверка: полный обход `index` + полный обход `batch` (и выполняет шаги удаления/пространства ниже) | выкл |
| `--check-deleted` | Также запустить `sync-deleted --online` для проверки и пометки удалённых на сервере тредов | выкл |
| `--refresh-spaces` | Также перестроить `spaces --fetch-meta` и запустить `sync-space` | выкл |
| `--limit N` / `--mode X` / `--delay-min` / `--delay-max` | Передаются в фазу `batch` | — |

Ключевое поведение:

- Запуск по умолчанию загружает только новые/обновлённые беседы и **пропускает обнаружение удалений и обновление пространств** — самый дешёвый вариант для частой синхронизации.
- Сверка удалений/пространств включается по желанию (`--check-deleted` / `--refresh-spaces`) или объединяется с помощью `--full`. Счётчик `index` (`incremental_runs_since_full`) является предохранителем: он напоминает, когда сверка `--full` просрочена.

```bash
pplx-export sync --account alice                     # conversations only (fast)
pplx-export sync --account alice --full              # periodic full reconciliation
pplx-export sync --account alice --check-deleted     # also mark remote deletions
```

## space-index

Извлечь список бесед "Все" одного пространства — включая треды, опубликованные другими участниками — в `index/space_<slug>.json`.

| Флаг | Значение | По умолчанию |
|---|---|---|
| `SPACE_URL` (позиционный) | URL страницы пространства | обязательно |
| `--transport webbridge` | Использовать устаревший путь рендеринга браузера вместо REST | `cookie` (REST напрямую) |

Ключевое поведение:

- Путь по умолчанию — REST напрямую: `list_collection_threads` через транспорт cookie с постраничной навигацией по смещению; строки включают `context_uuid` и `answer_preview`.
- С `--transport webbridge` он возвращается к прокрутке отрисованной страницы пространства и извлечению свойств строк — резервный вариант на случай изменения структуры REST.
- Строки записываются сначала новые по `lastUpdated`.

```bash
pplx-export space-index "https://www.perplexity.ai/spaces/<space-slug>" --account alice
```

## export

Экспортировать один тред (URL или чистый UUID) в его каталог архива `<out>/<account-folder>/<mode>/<thread-dir>/`.

| Флаг | Значение | По умолчанию |
|---|---|---|
| `THREAD` (позиционный) | URL треда или UUID | обязательно |
| `--force` | Повторный экспорт, даже если `lastUpdated` не изменился | выкл |

Ключевое поведение:

- Если архивная копия уже актуальна, экспорт пропускается без записи; `--force` переопределяет проверку.
- `lastUpdated` берётся из локального индекса библиотеки, когда тред там указан (та же семантика и формат, что и `batch`), в противном случае используется значение платформы.
- Конечные состояния регистрируются корректно, без трассировки: `ENTRY_DELETED` помечает `deleted` в `batch_state.json`, `ENTRY_EXPIRED` помечает `expired` — существующий локальный архив в любом случае остаётся нетронутым.
- Успешный экспорт записывает `ok` в `index/batch_state.json`, поэтому инкрементальный план считает тред "экспортированным и неизменённым".
- Что попадает в каталог треда: [archive-layout.md](archive-layout.md); конвейер экспорта: [../architecture/export-pipeline.md](../architecture/export-pipeline.md).

```bash
pplx-export export "https://www.perplexity.ai/search/<thread-uuid>" --account alice
```

## batch

Массовый экспорт тредов учётной записи — ежедневный драйвер, с инкрементальной ранней остановкой и возобновляемыми контрольными точками.

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--force` | Повторный экспорт всех тредов (конечные состояния исключены) | выкл |
| `--full` | Полное сканирование: неизменённые треды всё равно пропускаются, но ранней остановки нет | выкл |
| `--limit N` | Обработать только первые N строк списка (сначала новые) | все |
| `--mode MODE` | Экспортировать только треды `search` / `deep-research` / `computer` / `council` / `study` | все режимы |
| `--delay-min SEC` | Нижняя граница случайного интервала между тредами | `10` |
| `--delay-max SEC` | Верхняя граница случайного интервала между тредами | `20` |

Ключевое поведение:

- Требует `index/library_<account>.json` — сначала запустите `index`.
- По умолчанию **инкрементальная ранняя остановка**: список сортируется сначала новые, и завершающая последовательность "экспортированных и неизменённых" тредов отсекается целиком; пробелы, оставленные прерванными запусками (ошибка/никогда не экспортированы), находятся выше этого суффикса и всё равно исправляются. `--full` отключает раннюю остановку (периодический предохранитель или при подозрении на пробелы в архиве); `--force` повторно экспортирует всё, кроме конечных состояний, которые никогда не повторяются. Полная семантика: [incremental-sync.md](incremental-sync.md).
- Фильтрация `--mode`: строки, несущие `search_mode` (авторитетное поле платформы, обогащённое `search-mode-backfill`), сопоставляются точно через `SEARCH_MODE_MAP` — на этом пути `--mode search` больше не включает треды deep-research/council/study. Строки без `search_mode` возвращаются к эвристикам индекса: `computer` = режим `COMPUTER`; `deep-research` = displayModel `pplx_alpha`; `council` = `pplx_agentic_research`; `study` = `pplx_study`; `search` = оставшиеся строки режима `SEARCH` (включая эти три вида — отфильтруйте их точно, экспортируя конкретные режимы отдельно).
- Состояние сохраняется в `index/batch_state.json` после каждого треда — прерывайте и запускайте заново свободно.
- Быстрый отказ при аутентификации: 3 последовательных ответа 401/403 прерывают запуск (просроченный cookie не может самовосстановиться, и продолжение приводило бы к сотням ошибок один за другим).
- Темп: случайная пауза `--delay-min`–`--delay-max` между тредами; 429/5xx обрабатываются транспортным уровнем. Подробности: [rate-limiting.md](rate-limiting.md).
- Треды, попадающие на варианты переписанных ответов, регистрируются в `index/answer_variants_log.jsonl` с предупреждением о необходимости обработать их вручную как можно скорее (см. [../reference/api/api-responses-errors.md](../reference/api/api-responses-errors.md)).

```bash
pplx-export batch --account bob --mode deep-research --limit 50
```

## spaces

Перестроить индекс представления пространств — одна страница Markdown на пространство плюс реестр `spaces.json` — из локальных индексов библиотеки.

| Флаг | Значение | По умолчанию |
|---|---|---|
| `--fetch-meta` | Обновить метаданные владельца/участника перед перестроением | выкл |

Ключевое поведение:

- Без `--fetch-meta` команда является чисто локальной (ноль сети): она агрегирует треды по слагу пространства во всех файлах `library_*.json`, со статистикой участвующих учётных записей и обратными ссылками на каталоги экспортированных тредов.
- Вывод идёт в `./spaces/` относительно текущего рабочего каталога — запускайте её из каталога, содержащего `web_archive/`, чтобы обратные ссылки на страницах пространств разрешались.
- `--fetch-meta` сначала обновляет кеш владельца/участника каждого пространства через `get_collection` (1 запрос на пространство, интервал 3 с) в `index/space_meta.json`; когда текущая учётная запись не видит пространство, автоматически повторяется попытка с учётной записью, которая может его видеть (cookies переключаются сами).

```bash
pplx-export spaces --fetch-meta --account alice
```

## sync-space

Синхронизировать поле `space` уже заархивированных файлов `thread.json` с текущим индексом — чисто локально, ноль сети.

| Флаг | Значение | По умолчанию |
|---|---|---|
| *(только общие параметры; важен только `--out`)* | | |

Ключевое поведение:

- Предварительное условие: сначала запустите `index` — обновлённый `library_*.json` является источником истины для текущего владения пространством.
- Сравнивает слоги пространств для каждого треда и исправляет `thread.json` на месте при расхождении; первые 30 изменений регистрируются.
- После любого изменения индекс `spaces/` автоматически перестраивается.

```bash
pplx-export index --account alice && pplx-export sync-space
```

## schedule

Вычислить план инкрементального экспорта этого раунда и записать фрагмент cron, который системный cron может вызывать напрямую.

| Флаг | Значение | По умолчанию |
|---|---|---|
| *(только общие параметры)* | | |

Ключевое поведение:

- Загружает актуальный индекс и сообщает план в виде количества всего/нового/обновлённого, используя ту же чистую функцию ранней остановки (`plan_incremental`), что и `batch` — см. [incremental-sync.md](incremental-sync.md).
- Записывает `<out>/index/cron_snippet.txt`, содержащий одну строку `17 3 * * *` вида `cd '<archive-parent>' && '<abs-path-to-pplx-export>' batch --account '<account>' --out '<abs-archive-root>'` — пути абсолютные и в кавычках, так как cwd и PATH cron непредсказуемы. Путь к исполняемому файлу разрешается через `shutil.which`; если это не удаётся, фрагмент возвращается к простому имени `pplx-export`.
- Запланированные запуски по замыслу только инкрементальные; запускайте `batch --full` вручную в качестве периодического предохранителя.

```bash
pplx-export schedule --account alice
```
