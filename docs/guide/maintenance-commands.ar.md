# أوامر الصيانة

تحافظ الأوامر الفرعية للصيانة في `pplx-export` على سلامة الأرشيف الحالي: إعادة عرض الصفحات بعد إصلاحات العارض، وملء الأصول / استخدام الرصيد / بيانات الوضع، ووضع علامة على المحادثات المحذوفة عن بُعد، وإعادة بناء رسم بياني للعلاقات. معظمها يعمل دون اتصال أولاً؛ وتتبع مراحلها عبر الإنترنت نفس نظام التوقيت الخاص بـ `batch` (انظر [rate-limiting.md](rate-limiting.md)). جميعها تقبل [الخيارات المشتركة](pplx-export.md) (`--account`، `--out`، `--cookies-from`، `--transport`، …).

- مبدأ الاحتفاظ بالأرشيف المحلي: لا يقوم أي أمر صيانة بحذف أو نقل محتوى المحادثات المؤرشفة — الأرشيف هو النسخة الاحتياطية.
- الأوامر غير المتصلة (`re-render`، `relations`، `sync-space`، `spaces` بدون `--fetch-meta`، والمراحل الافتراضية أدناه) لا تحتاج إلى أي نقل على الإطلاق؛ انظر [../architecture/offline-operations.md](../architecture/offline-operations.md).

<a id="re-render" data-pplx-source-anchor="true"></a>
## إعادة العرض

إعادة إنشاء `conversation.md` و `turns/` من JSON الخام المؤرشف (`raw_entries.json` / `raw_blocks.json`) بعد إصلاحات العارض — بدون شبكة، ويتم ترك كل ملف آخر دون تغيير.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `--limit N` | معالجة أول N دليل محادثة فقط | الكل |
| `--dry-run` | سرد الأدلة التي ستتم معالجتها، دون كتابة شيء | إيقاف |
| `--thread-json` | إضافة/إزالة مفتاحي `interruptions` و `answer_variants` في `thread.json` في مكانها | إيقاف |

السلوكيات الرئيسية:

- إعادة البناء تعمل دون اتصال بنفس خط أنابيب التصدير: التحليل، الترتيب حسب `created_us`، إزالة الازدواجية في الاستشهادات، وبالنسبة لوضعي الكمبيوتر/المجلس — كتل سير العمل، ورسم الخرائط للوكلاء الفرعيين، وملحق الخلفية غير المستهلكة.
- يتم (إعادة) كتابة `conversation.md` و `turns/turn_*.md` فقط؛ بينما تبقى `sources*`، `assets/`، `report.md` و `thread.json` كما هي. يتم حذف ملفات `turn_*.md` القديمة التي يزيد رقمها عن عدد الأدوار الحالي — لا شيء غير ذلك، لذا تحتفظ الملفات غير المتغيرة بوقت تعديلها.
- `--thread-json` يكتب فقط عندما يتغير المحتوى فعليًا؛ `answer_variants` الجديدة/المعدلة تثير تحذير `ANSWER_VARIANT_DETECTED` وتُضاف إلى `index/answer_variants_log.jsonl` (عمليات إعادة التشغيل المتطابقة لا تسبب تكرارًا).
- يتم تخطي أدلة المحادثات التي لا تحتوي على `raw_entries.json` ويتم عدها.

```bash
pplx-export re-render --limit 20 --thread-json --dry-run
```

<a id="assets-backfill" data-pplx-source-anchor="true"></a>
## ملء الأصول

معالجة الأصول التي تم أرشفتها بدون رابط موقع — ثلاثة علاجات مرحلية: إعادة جلب الكتل المفقودة، الاستخراج المضمن دون اتصال، والتحديث عبر الإنترنت اختياريًا.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `--fetch-blocks` | إعادة جلب `raw_blocks.json` المفقودة وأصول روابطها الموقعة أولاً (عبر الإنترنت) | إيقاف |
| `--online` | تمكين التحديث عبر الإنترنت للأصول المفقودة/القديمة | إيقاف (استخراج مضمن دون اتصال فقط، بدون طلبات) |
| `--limit N` | معالجة أول N دليل محادثة فقط | الكل |

السلوكيات الرئيسية:

- المرحلة الافتراضية (دون اتصال، بدون طلبات): استخراج الأصول المضمنة (`ASSET_DIFF` / `CODE_ASSET`) من `raw_blocks.json` إلى `assets/files/*.md`، وتسجيل أنواع مقابض مساحة العمل السحابية (`DOC_FILE` / `CODE_FILE` / `UNKNOWN` — لا توجد قناة تنزيل بعد) في `assets/assets_manifest.json`. متطابقة: يتم إلغاء ازدواجية السجلات المعروفة بواسطة uuid، ثم file_handle؛ الملفات متعددة الإصدارات التي تحمل نفس الاسم تحصل على لاحقة قصيرة من uuid حتى لا تتعارض عمليات إعادة التشغيل.
- `--fetch-blocks` (عبر الإنترنت): إعادة جلب `raw_blocks.json` المفقودة لمحادثات البحث العميق/الكمبيوتر/المجلس/الدراسة بالإضافة إلى أصولها القابلة للتنزيل؛ يتم تجميع المحادثات حسب مجلد الحساب مع محول مبني بتكاسل لكل حساب (ملفات تعريف الارتباط تتبدل تلقائيًا)، 3 ثوانٍ بين المحادثات.
- `--online`: لإصدارات البيان التي يكون `downloaded_to` فيها مفقودًا/قديمًا، جلب رابط موقع جديد عبر `/rest/assets/<uuid>/data` (استدعاءات API متسلسلة، بفارق 3 ثوانٍ)، ثم إعادة التنزيل من CDN (6 محادثات متزامنة، بدون تأخير — CDN، وليس API). خطأ 404 `ASSET_NOT_FOUND` يضبط العلم النهائي `asset_expired`؛ خطأ 403 عبر الحسابات يُعاد محاولته مرة واحدة مع الحساب الذي يملك مجلد الأرشيف.
- يتم إعادة حساب `count` للبيان كإجمالي عدد الإصدارات عند كل كتابة.

```bash
pplx-export assets-backfill --fetch-blocks --online --limit 30 --account alice
```

## ملء الاستخدام

ملء استخدام الرصيد لكل محادثة (`credits/thread-usage`) لجميع محادثات الحساب المؤرشفة في `index/credit_usage_<account>.json`.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `--limit N` | معالجة أول N محادثة فقط | الكل |

السلوكيات الرئيسية:

- طلب GET واحد لكل محادثة مؤرشفة (`thread_id` = `psc_uuid` للمحادثة)، بفارق 3 ثوانٍ؛ متطابقة — يتم تخطي المحادثات الموجودة بالفعل في ملف الإخراج.
- خطأ 403 (`thread_usage_forbidden`، أي محادثة عبر الحسابات) يُسجل كـ `error` ولا يُعاد محاولته أبدًا؛ تُترك حالات الفشل الأخرى للتشغيل التالي. يتم حفظ التقدم كل 25 محادثة تمت معالجتها.
- حسابات متعددة: تشغيل مرة واحدة لكل حساب مع `--account` — تتبدل ملفات تعريف الارتباط تلقائيًا بين عمليات التشغيل.

```bash
pplx-export usage-backfill --account alice
```

## ملء وضع البحث

ملء الحقل `search_mode` الموثوق من المنصة في كل صف من `index/library_<account>.json`، بحيث يمكن لـ `batch --mode` التصفية بدقة بدلاً من الاعتماد على الاستدلال.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `--limit N` | معالجة أول N صف معلق فقط | الكل |
| `--offline` | استخراج محلي فقط — الصفوف التي لا تحتوي على بيانات خام محلية تنتظر الجولة التالية، بدون تراجع عبر الإنترنت | إيقاف |
| `--delay-min SEC` | الحد الأدنى للفاصل الزمني العشوائي بين محادثات التراجع عبر الإنترنت | `10` |
| `--delay-max SEC` | الحد الأعلى للفاصل الزمني العشوائي بين محادثات التراجع عبر الإنترنت | `20` |

السلوكيات الرئيسية:

- يخزن القيمة الخام للمنصة (`SEARCH` / `RESEARCH` / `ASI` / `AGENTIC_RESEARCH` / `STUDY` / `STUDIO`…)؛ المحادثة التي تحمل قيمًا متعددة تحتفظ بالأكثر تحديدًا حسب: كمبيوتر > مجلس > دراسة > بحث عميق > بحث.
- محلي أولاً: المحادثات المؤرشفة تُحل من `raw_entries.json` بدون شبكة — التشغيل المحلي بالكامل لا يبني حتى أي نقل (ولا حتى اختبار جلسة).
- التراجع عبر الإنترنت فقط للصفوف التي لا تحتوي على بيانات خام محلية: `GET /rest/thread/<uuid>` بفاصل زمني عشوائي 10–20 ثانية؛ الصفوف في الحالة النهائية `expired` يتم تخطيها وتسجيلها؛ المحادثات التي تم العثور عليها منتهية الصلاحية/محذوفة عبر الإنترنت يتم وضع علامة عليها في `batch_state.json` لتوفير الطلبات المستقبلية.
- متطابقة وقابلة للاستئناف: الصفوف التي تحتوي بالفعل على `search_mode` يتم تخطيها، ويتم حفظ التقدم كل 25 صفًا، وعمليات تحديث `index` اللاحقة تحافظ على الإثراء (يتم دمجها مرة أخرى بواسطة `entryUUID`).

```bash
pplx-export search-mode-backfill --account alice --offline
```

## مزامنة المحذوفات

تحديد المحادثات التي اختفت من المكتبة البعيدة (محذوفة من قبل المستخدم أو المنصة) ووضع علامة شاهد قبر عليها — لا تحذف أو تنقل أي ملف أرشيف.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `--online` | التحقق من كل مرشح عبر الإنترنت | إيقاف (تشغيل تجريبي دون اتصال: سرد المرشحين فقط) |
| `--limit N` | معالجة أول N مرشح فقط | الكل |
| `--delay-min SEC` | الحد الأدنى للفاصل الزمني العشوائي بين المرشحين | `10` |
| `--delay-max SEC` | الحد الأعلى للفاصل الزمني العشوائي بين المرشحين | `20` |

السلوكيات الرئيسية:

- اكتشاف المرشحين يتم دون اتصال وعبر الحسابات: محادثة بحالة `batch_state` `ok` ومفقودة من اتحاد `entryUUID` لجميع ملفات `index/library_*.json` تصبح مرشحة — أي فهرس واحد يحتوي عليها يعتبر حيًا، لذا لا يتم إنشاء نتائج إيجابية خاطئة للمحادثات المصدرة عبر الحسابات عبر المساحات المشتركة. عندما لا يوجد فهرس قابل للاستخدام، يتم تخطي كل شيء بأمان مع تلميح لتشغيل `index` أولاً.
- الافتراضي هو تشغيل تجريبي دون اتصال: يسرد المرشحين وأسباب التخطي الآمن — بدون شبكة، بدون كتابة.
- `--online` يتحقق من كل مرشح باستخدام `GET /rest/thread/<uuid>` تحت الحساب المسجل في `thread.json` `export_via` (ملفات تعريف الارتباط تتبدل تلقائيًا لكل مرشح).
- التأكيد بواسطة `ENTRY_DELETED` / `ENTRY_EXPIRED` / HTTP 404 → `batch_state` يضع علامة على الحالة النهائية `deleted` (نفس دلالات `expired`: لا يُعاد محاولته أبدًا، `--force` لا يعيد التصدير؛ انظر [incremental-sync.md](incremental-sync.md)) ويحصل كل ملف من ملفات `thread.json` للمحادثة على طابع زمني `remote_deleted` في مكانه (متطابق — يتم الاحتفاظ بالمفتاح الموجود).
- المحادثة لا تزال موجودة → نتيجة إيجابية خاطئة: يتم الإبلاغ عنها كما هي مع تلميح لإعادة تشغيل `index`، لم يتغير شيء. أخطاء النقل تتراجع إلى الجولة التالية؛ 3 حالات فشل متتالية في المصادقة توقف التشغيل قبل وضع علامة خاطئة على أي شيء.

```bash
pplx-export sync-deleted
pplx-export sync-deleted --online --limit 20
```

التشغيل الأول يسرد المرشحين (تشغيل تجريبي دون اتصال)؛ الثاني يتحقق منهم عبر الإنترنت ويضع علامة شاهد قبر على المؤكدين.

<a id="status" data-pplx-source-anchor="true"></a>
## الحالة

طباعة حالة حساب الأرشيف وخطة التغيير التدريجي — بدون شبكة، للقراءة فقط. يجيب على "كيف يبدو الأرشيف الآن، وماذا سيفعل تشغيل `batch` التالي" دون لمس الشبكة.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `--account X` | الإبلاغ عن حساب واحد فقط | جميع الحسابات التي لديها ملف `index/library_*.json` |
| `--json` | تقرير كامل قابل للقراءة آليًا على stdout (يتجاهل مستوى التفصيل) | إيقاف (سطور سجل بشرية) |

السلوكيات الرئيسية:

- مصادر البيانات محلية بحتة: `index/library_*.json` (صفوف الفهرس لكل حساب) و `index/batch_state.json` (المصدر الوحيد لحالات التصدير). إعادة استخدام تصنيف التغيير لنفس الدالة البحتة `plan_incremental` مثل `batch`/`schedule`، لذا فإن دلالات `new`/`updated`/`done`/`expired`/`deleted` مطابقة لما ستحسبه `batch`.
- مخرجات INFO الافتراضية تطبع سطرًا ملخصًا واحدًا لكل حساب (عدد الفهرس + الحداثة، أعداد حالة `ok/expired/deleted/error`، أعداد تغيير `new/updated`، ورقم الإيقاف المبكر) بالإضافة إلى سطر حساب `batch_state` عالمي (مثل `559 ok + 13 expired + 12 deleted`).
- مستويات التفاصيل تركب على علم التفصيل القياسي: `-v` يضيف عناوين محادثات `new`/`updated`/`error` (السطر الأول، مقتطع إلى 60 حرفًا)؛ `-vv` يضيف محادثات `done`/`expired`/`deleted` مع `lastUpdated`/`exported_at`؛ `-vvv` يطبع كل شيء بدون اقتطاع مع حقول الفهرس `mode`/`search_mode` وقائمة الحالة فقط (السجلات الموجودة في `batch_state` ولكنها مفقودة من فهرس كل حساب — مرشحون للحذف عن بُعد للتوفيق مع [sync-deleted](#sync-deleted)).
- حواجز الحماية: ملف `index/` مفقود أو ملف مكتبة مفقود يخرج بخطأ يشير إلى `pplx-export index`؛ ملف `batch_state.json` مفقود يُعتبر حالة فارغة (كل شيء يُحسب كـ `new`). لا يلزم تكوين على مستوى المستخدم — يتم تعداد الحسابات من أسماء ملفات المكتبة.
- `--json` يصدر التقرير الكامل (الحسابات، التغييرات، المحادثات، الحالة فقط، الإجماليات) كـ JSON بسطر واحد على stdout — نفس نمط العقد مثل `pplx-ask`.

```bash
pplx-export status                 # summary for every account
pplx-export status -vv             # five-state thread details
pplx-export status --account alice --json
```

## العلاقات

إعادة بناء رسم بياني لعلاقات المحادثة من المحادثات المصدرة → `relations/edges.jsonl` بالإضافة إلى `relations/graph.md` قابل للقراءة البشرية تحت جذر الأرشيف.

| العلم | المعنى | الافتراضي |
|---|---|---|
| *(الخيارات المشتركة فقط؛ `--out` فقط هو المهم)* | | |

السلوكيات الرئيسية:

- دون اتصال بحت، بدون شبكة، للقراءة فقط ضد الأرشيف: يعيد استخدام خط أنابيب إعادة البناء دون اتصال الخاص بإعادة العرض (`raw_entries.json` / `raw_blocks.json`)، لذا فإن إشارات `sub_agents`، `query_source` والاستشهادات متاحة جميعًا لاكتشاف الحواف.
- المحادثات بدون بيانات خام تتحول إلى هيكل `thread.json` + `conversation.md` — فقط حواف مرجع `same_space` و uuid المجرد يمكن أن تنطلق لها.

```bash
pplx-export relations
```

## debug-js

تنفيذ مقتطف JavaScript في سياق صفحة المتصفح الحالية عبر برنامج WebBridge الخفي المحلي (`127.0.0.1:10086`) وطباعة النتيجة كـ JSON — فتحة هروب للتصحيح.

| العلم | المعنى | الافتراضي |
|---|---|---|
| `JS代码` (موضعي) | كود JavaScript لتقييمه في سياق الصفحة (المعامل argparse الحرفي) | مطلوب |

السلوكيات الرئيسية:

- يتطلب أن يكون برنامج WebBridge الخفي قابلاً للوصول وأن تكون صفحة Perplexity الهدف مفتوحة في المتصفح؛ يتم تشغيل المقتطف مع جلسة الصفحة الخاصة.
- يتم اقتطاع JSON المطبوع عند 5000 حرف.

```bash
pplx-export debug-js 'document.title'
```
