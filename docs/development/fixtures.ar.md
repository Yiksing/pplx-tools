# تركيبات الاختبار

`tests/fixtures/` تحتوي على **بيانات محاكاة** حتمية الشكل مشابهة لواجهة API لـ
[مجموعة الاختبار](testing.md). تمثل المدخلات هياكل خيط وعمل نموذجية؛
يتم حفظ منتجاتها المقدمة كلقطات ذهبية.

<a id="source-contract" data-pplx-source-anchor="true"></a>
## عقد المصدر

<!-- audit:contract fixture-source=simulated -->

محتوى التركيبة الملتزم بها حاليًا هو محاكى:

- يجب إنشاء التركيبات الجديدة أو المحدثة كبيانات محاكاة؛ يجب على المساهمين
  عدم تعبئتها عن طريق استيراد `web_archive/` أو بيانات حساب المستخدم أو استجابات
  API الحية أو الأرشيفات الخاصة.
- الأسماء والهويات والمعرفات والاستفسارات والإجابات وحمولات العمل والمسارات
  وعناوين URL في الملفات الملتزم بها هي عناصر نائبة للاختبار.
- يعكس JSON مخططات استجابة الإنتاج والأرشيف فقط لاختبار سلوك المحلل اللغوي
  والمقدم والحالة والعلاقة.
- لا يلتزم المستودع بتعيين عكسي من العناصر النائبة إلى المعرفات الخاصة.

يصف المصطلحان **تركيبة الوضع الكامل** و**تركيبة السيناريو المصغر** تغطية
الاختبار وشكل المدخلات، وليس الأصل. كلاهما بيانات محاكاة.

<a id="directory-contract" data-pplx-source-anchor="true"></a>
## عقد الدليل

يحتوي كل دليل تركيبة على مدخلات محاكاة بشكل استجابة خام، وعند الحاجة إلى مقارنة
لقطة، شجرة `golden/`:

| المسار | الدور |
|---|---|
| `raw_entries.json` | إدخالات خيط محاكاة بشكل استجابة الإنتاج |
| `raw_blocks.json` | كتل عمل محاكاة؛ غائبة عندما لا يحتوي الوضع على استجابة كتلة |
| `thread.json` | بيانات وصفية لخيط مؤرشف محاكى |
| `golden/conversation.md` + `golden/turns/turn_*.md` | منتجات مولدة من المدخلات المحاكاة ومقارنة بايت ببايت |

تشمل الاصطلاحات الحتمية الحالية:

- حسابات نائبة `alice` / `bob`، هويات مثال، مساحة BOT نائبة،
  و `read_write_token` نائب ثابت؛
- معرفات مشتقة من uuid5 موسومة بـ `5cbeef00`، تحافظ على المراجع المتقاطعة
  المقصودة بين السجلات المحاكاة؛
- معرفات `toolu_` محاكاة ذات طول ثابت موسومة بـ `5crub0`؛
- استفسارات وعناوين ونص عمل ومسارات ملفات عامة؛ و
- سلاسل استعلام URL الموقعة تمت إزالتها.

تسهل هذه الاصطلاحات اكتشاف أي بقايا عرضية خاصة بالبيئة؛
لا تعني أن المعرفات المحاكاة مشتقة من كائنات حية.

## صيانة التركيبات

يقوم `tests/scrub_fixtures.py` بتطبيع البيانات المحاكاة، وإعادة توليد المنتجات
الذهبية من خلال عارض الإنتاج دون اتصال، ويفرض بوابة بقايا:

```bash
uv run python tests/scrub_fixtures.py
uv run python tests/scrub_fixtures.py --check
```

- **إعادة التوليد** — يتم عرض كل تركيبة في دليل مؤقت من خلال
  `pplx_export.commands.rerender_cmd.rerender`؛ عدم تطابق عدد الدورات يؤدي إلى الإنهاء.
- **التطبيع الحتمي** — يتم تطبيع النص النائب، UUIDs، قيم `toolu_`،
  الرموز، وعناوين URL الموقعة بشكل متكرر.
- **مدخلات الأمان ليست أصلاً** — `tests/scrub_pairs.local.json` المحلي الاختياري
  وتكوين حساب على مستوى المستخدم يوسعان فقط فحوصات الاستبدال والبقايا.
  يجب عدم استخدامهما كمدخلات لبناء سيناريوهات التركيبة.
- **وضع الفحص** — `--check` لا يقوم بأي كتابة ويفشل عند وجود بقايا
  مهيأة، أو مسارات محلية مطلقة، أو بيانات اعتماد URL موقعة.

قم بتشغيل أداة الصيانة بعد تغيير JSON المدخل المحاكى أو مخرج العارض،
وقم بتشغيل `--check` قبل التزام تغييرات التركيبة.

## سلطة اللقطة الذهبية

JSON المحاكى الملتزم به هو سلطة الإدخال. Markdown الذهبي هو مخرج مشتق:
يتم إعادة توليده من ذلك JSON باستخدام مسار إعادة العرض الحالي للإنتاج ثم
يتم التزامه لمقارنة الانحدار على مستوى البايت. يجب عدم تحريره كمصدر حقيقة
مستقل.
