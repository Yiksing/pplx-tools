# بنية الاختبار

نظام اختبار `pplx_export` غير متصل بالإنترنت بالكامل، ويستخدم بيانات محاكاة تم التحقق منها، ويقوم بقفل لقطات سلوك العارض. تصف هذه الصفحة البنية والضمانات؛ قائمة الوحدات الحالية موجودة في [Testing](../development/testing.md)، وتفاصيل التركيبات موجودة في [Test fixtures](../development/fixtures.md).

يحتفظ القسم بترقيمه من [نظرة عامة على البنية](../architecture/overview.md).

---

<a id="test-system" data-pplx-source-anchor="true"></a>
## نظام الاختبار

قم بتشغيل المجموعة باستخدام `uv run pytest tests`. يتم الإبلاغ عن أعداد الاختبارات من التشغيل الحالي بدلاً من معاملتها كثابت معماري.

<a id="layers" data-pplx-source-anchor="true"></a>
### الطبقات

| الطبقة | الوحدات النمطية الممثلة | العقد |
|---|---|---|
| سلوك الوحدة النقية | `test_units.py`، اختبارات بيانات الاعتماد/الكوكيز/التكوين | عزل الدوال والفئات والتحقق من الصحة والتطبيع باستخدام مدخلات محاكاة |
| دلالات المكونات | اختبارات المقاطعة، سير العمل النموذجي، تنوع الإجابة، والعلاقات | ممارسة التعاون بين محلل الشفرة والعارض والحالة والفهرس دون الوصول إلى الشبكة |
| سلوك الأوامر/الحالة دون اتصال | اختبارات التعبئة، مزامنة الحذف، التهيئة، ومراجعة الانحدارات | تشغيل مسارات الأوامر مقابل أدلة مؤقتة ونقل مزيف |
| لقطات العارض | `test_render_snapshots.py` | تمرير JSON محاكى بشكل API عبر مسار إعادة العرض الإنتاجي ومقارنة جميع بايتات Markdown مع القوالب الذهبية الملتزمة |

معرفات المراجعة مثل N وV3 وV4 وV5 هي بيانات تتبع عبر هذه الطبقات. لا تحدد بنية تشغيل منفصلة، وعلاقتها بوحدات الاختبار ليست بالضرورة واحد لواحد.

<a id="snapshot-data-flow" data-pplx-source-anchor="true"></a>
### تدفق بيانات اللقطة

1. يوفر تركيب محاكى `raw_entries.json`، واختياريًا `raw_blocks.json`، و`thread.json`.
2. ينسخ `tests/conftest.py::render_fixture` تلك الملفات إلى `tmp_path`.
3. يستدعي التركيب `commands.rerender_cmd.rerender`، مسار إعادة البناء دون اتصال الإنتاجي.
4. تتم مقارنة ملفات `conversation.md` و`turns/turn_*.md` الجديدة بايت ببايت مع منتجات `golden/` الملتزمة.

القوالب الذهبية هي توقعات مولدة، وليست مصدر بيانات مستقل. أي تغيير في العارض يغير بايتات القطعة يحول مجموعة اللقطات إلى اللون الأحمر حتى تتم مراجعة التغيير وإعادة توليد القوالب الذهبية عن قصد.

<a id="isolation-and-trust-boundaries" data-pplx-source-anchor="true"></a>
### حدود العزل والثقة

- **أصل التركيب** — جميع مدخلات التركيب الملتزمة هي بيانات محاكاة. لا يتم نسخها من حسابات حية، أو استجابات API حية، أو `web_archive/`، أو أرشيفات خاصة.
- **حدود الشبكة** — تستخدم الاختبارات مسارات مزيفة وغير متصلة؛ التركيبات الملتزمة لا تتطلب بيانات اعتماد أو وصول إلى الشبكة.
- **حدود التكوين** — يقوم التركيب التلقائي بتثبيت تكوين حساب نائب، لذا فإن `~/.config` الحقيقي للمطور لا يحدد النتائج.
- **حدود نظام الملفات** — يعمل سلوك الأوامر والترحيل تحت `tmp_path`؛ أرشيفات المستخدم ليست أهداف اختبار.
- **حدود البقايا** — يرفض `tests/scrub_fixtures.py --check` سلاسل محددة بالبيئة تم تكوينها، ومسارات مطلقة محلية، وبيانات اعتماد URL موقعة دون تعديل الملفات.

معًا، تحمي تأكيدات الوحدة، ودلالات المكونات، واختبارات حالة الأوامر، ولقطات البايت كلاً من المنطق المحلي وعقد إعادة العرض من البداية إلى النهاية.
